# EXTERNAL_CROSSWALK

Read **after** `REPO_NATIVE_OPERATING_SYSTEM.md` §B–§F were reconstructed. External standards are
used here for the three permitted purposes only:

1. identify a critical capability the repository never discovered;
2. falsify or narrow a repo-native principle;
3. find a standard implementation of something already discovered internally.

The repository's language is preserved wherever it is more precise, and it usually is: an external
standard names a *property to have*, and this repository names *the failure that made it necessary*.

## The three findings that matter

**1. One critical capability the repository never discovered: machine-readable provenance edges.**
W3C PROV's `wasRevisionOf` / `wasInvalidatedBy` and RO-Crate's packaging are the standard form of
what `L10` does in prose. The repository's supersession chains are complete and correct and are
readable only by a person. Making them edges would let a *scan* answer "is this result current?" —
which is `LOCAL_SOLUTION_GAPS.md` G-04 with a vocabulary attached.

**2. One narrowing of a repo-native principle.** `L1 derive, don't declare` reads, at first, like
GitOps. It is the opposite: GitOps holds the declaration authoritative and converges the world;
this repository holds the world authoritative and converges the declaration. **The law should be
stated with its direction**, because importing GitOps' framing would invert it. It is now stated
that way in `REPO_NATIVE_OPERATING_SYSTEM.md` §B.

**3. One ceiling the repository has not written down.** ACM's `Results Replicated` — obtained by
others *without* the authors' artifacts — is unreachable here by construction, because every
independent review reads this repository's own artifacts. `E6` currently reads as though it were
the top. It is not; it is the top of what a single-repository study can reach.

## What was deliberately not imported

| standard | why not |
| --- | --- |
| ISO/IEC 25010 as a taxonomy for the debt register | the register's `type` field (correctness · evidence · representation · UX · research · ops) is already in use, has a closed vocabulary enforced by `register-scan.ts`, and maps to what *this* product can be wrong about. Renaming six categories to nine ISO characteristics would cost the enforcement and buy a vocabulary nobody here asks in. |
| ADR templates | the repository's decision files carry claim, alternatives, external implementations, what was copied/wrapped/referenced, local evidence, counterevidence, uncertainty, decision, and reversal condition. An ADR template carries four of those nine. |
| Fitness-function framing for gates | it has no positive-control requirement, and adopting the name without the requirement is exactly how `L4` would be lost. |
